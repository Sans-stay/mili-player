# Mili 播放器

以**悬浮字幕**为核心的音乐播放器：歌词以透明、无边框、置顶的字幕浮在桌面上，
逐字点亮、跟随播放进度。视觉参考 Limbus Company 每章终战的背景歌词演出。

## 功能

| | |
| --- | --- |
| **散落歌词**（默认） | 全屏随机落点、各自倾斜、逐字浮现、逐字微颤 |
| **底部字幕条** | 透明窄窗，上一行 / 当前行 / 下一行，可拖动 |
| **歌词色号** | 11 个内置主题色，可改名、可增删、可存新色 |
| **歌曲彩蛋** | 识别到特定曲目自动切主题色（Mili 曲子为主，也可配非 Mili） |
| **本地播放** | 打开或拖入音频文件，读 ID3 标签，自动去音乐源配歌词 |
| **在线播放** | 应用内登录 QQ 音乐，搜索后直接在线播放 |
| **多音乐源** | QQ 音乐 / 网易云 / 酷狗，搜索面板一键切换 |
| **播放列表** | 本地文件与在线曲目混在一起，顺序 / 随机播放，可批量增删、全选 |
| **逐字歌词** | LRC / 增强 LRC / QQ 音乐 QRC / 酷狗 KRC |
| 托盘 + 快捷键 | 托盘菜单控制播放；`Ctrl + Alt + L` 切换鼠标穿透 |

## 怎么打开

**方式一 · 双击启动脚本**（推荐）

| 文件 | 说明 |
| --- | --- |
| `启动 Mili 播放器（无窗口）.vbs` | 不弹控制台，日常用这个 |
| `启动 Mili 播放器.cmd` | 保留控制台，出问题时看日志 |

**方式二 · 打包版**

```bash
npm run package
```

产物在 `dist\Mili播放器-win32-x64\`，整个文件夹可独立运行，
设置与登录态写在该文件夹的 `data\` 下。

> ⚠️ 请双击同目录下的 `启动 Mili 播放器.vbs`，**不要直接双击 `Mili播放器.exe`**。

**方式三 · 命令行**

```bash
npm install
npm start          # 启动
npm run dev        # 带 DevTools
npm test           # 回归测试
```

<details>
<summary>为什么不能直接双击 exe / 为什么要加 <code>--no-sandbox</code></summary>

某些 Windows 环境里 Chromium 自己的沙箱起不来，启动会**瞬间崩溃**。
实测（`node scripts/probe-sandbox.js` 可复现）：崩溃发生在**主进程脚本执行之前** ——
连第一行 `console.log` 都没机会跑，所以应用内部无法自救，只能由命令行带上 `--no-sandbox`。

于是：

- **开发模式**：`scripts/start.js` 先按默认跑一次，8 秒内异常退出就自动加参数重试
- **打包版**：打包时自动在 exe 旁边放一个 `启动 Mili 播放器.vbs`，替你加上参数

环境修好了（换机器、关掉冲突的安全软件）的话，直接双击 `Mili播放器.exe` 即可恢复沙箱隔离。

</details>

## 界面与操作

**主窗口**：顶部是悬浮歌词开关 / 样式面板 / 最小化 / 退出；中部是封面、歌曲信息、
进度条、播放控制；下部是歌词列表，当前行逐字点亮，**点任意一行可跳转**。

| 快捷键 | 作用 |
| --- | --- |
| `空格` | 播放 / 暂停 |
| `←` `→` | 后退 / 前进 5 秒 |

点标题栏的文件夹按钮，或**把音频文件拖进窗口**即可播放。支持 mp3 / flac / m4a / aac / wav / ogg / opus。

### 散落歌词（默认）

每句在**屏幕内随机落点**、**各自倾斜**、**跟着歌声逐字浮现**，唱完停留一会儿再淡出。

- 悬浮窗铺满整个屏幕（透明 + 置顶），**强制鼠标穿透**且不可聚焦，不挡操作
- 落点按「倾斜后的外接矩形」计算并留边距，**整块文字永远不出屏**；新句子尽量不压已有的
- **倾角在「下限～上限」之间均匀随机**，正负方向也随机。改上下限时已有句子**原地平滑重落**，
  不会重掷角度或挪动落点
- **每个字都在微微颤抖**（周期 1.7–3.0 秒、相位随机），呈现游戏里那种不稳的手感
- **通篇不用白色**：正在唱的字也是主题色，只把外发光打得更烈
- 可调：倾角上下限、同屏句数、停留时长、字号随机、微颤开关

### 底部字幕条

一条透明窄窗，可拖动、位置会记住。

| 操作 | 说明 |
| --- | --- |
| 按住拖动 | 移动字幕 |
| 右键 | 打开主窗口 / 锁定 / 重置位置 / 隐藏 / 退出 |
| `Ctrl + Alt + L` | 全局快捷键，锁定或解锁鼠标穿透 |

### 歌词延迟

声音和歌词对不齐时，用样式面板里的「**歌词延迟**」滑杆整体平移，范围 −5 ~ +5 秒。

| 现象 | 怎么调 |
| --- | --- |
| 歌词出现得**比声音早** | 往**右**拉（正数），把歌词往后推 |
| 歌词出现得**比声音晚** | 往**左**拉（负数） |

滑杆**双击**或在下面点「归零」即可复位。

对不齐的原因通常不在你：音源本身带了静音头、LRC 打轴偏了、蓝牙耳机有传输延迟，都有可能。
与其去改歌词文件，不如给一个统一的偏置 —— 设置会存下来，重启仍然有效。

> 两个窗口都按「**播放时间 − 延迟**」取歌词，**逐字高亮和句子切换用的是同一条时间轴**。
> 这点很重要：只偏移一半的话，会出现「句子对上了、字还差一截」这种更难忍的半对齐。

### 播放列表

标题栏的列表按钮打开歌单面板。**本地文件和 QQ 音乐曲目混在同一个列表里**，
存在 `data/playlist.json`，重启后还在。

![播放列表](docs/playlist.png)

| 操作 | 说明 |
| --- | --- |
| 点歌名 | 播放这一首 |
| 勾选 + **全选** | 批量选中；全选框在部分选中时显示为半选 |
| **播放选中** | 从勾选的第一首开始播 |
| **移除选中** | 一次删掉所有勾选的 |
| 每行右侧 × | 单独移除这一首 |
| **清空** | 清空整个歌单 |
| **添加文件** | 选多个音频文件加进歌单 |
| **添加文件夹** | 递归扫描整个文件夹（含子目录）里的音频，一次全部加入 |

> **本地文件的封面不写进歌单文件。** 内嵌封面动辄上百 KB 的 base64，
> 几十首就能把 `playlist.json` 撑到几 MB（实测 26 首 = 2.9 MB，其中 2.87 MB 是封面），
> 而每次改歌单都要把整个文件重新序列化一遍。
> 所以存盘时会剥掉，启动后在后台按需回填 —— 界面上照常显示，文件只有几十 KB。

#### 给本地曲目绑定歌词

本地文件是拿「文件名 / ID3 标签」去 QQ 音乐**猜**歌词的，难免猜错。歌单里
**本地曲目**那一行右边有个「**词**」按钮，用它手动指定：

1. 点「词」→ 跳到搜索面板，顶部出现横幅「给《XXX》挑歌词」
2. 搜到正确的那首，**点它的歌名**（这个模式下点歌名 = 绑定，而不是平时的「只载入歌词」）
3. 绑定完成，横幅收起，回到歌单

已经绑过的曲目，按钮会高亮，副标题也会写出绑定到了哪首。想换绑重新点一次；
想解绑，进绑定模式点横幅上的「取消绑定」。

**自动匹配的结果也会被记下来。** 第一次播放本地曲目时照旧去搜一遍，
匹配成功就把结果存进歌单项 —— 之后再放这首：

- **不用再搜**（省掉那一两秒的等待）
- **不会因为搜索排序变了而忽然配成另一首**

绑定的代价极小：只存 QQ 音乐的 mid 和歌名/歌手几个字段，几十字节。

> **从歌单删掉这首，绑定自然就没了。** 绑定挂在歌单项自己身上，
> 不需要在别处维护一张「谁绑了谁」的表；删的时候还会顺手释放它独占的歌词缓存
> （歌词只在本次运行内缓存，不落盘，所以歌单文件不会因为绑定而变大）。

**播放模式**在面板顶部切换，四态和 QQ 音乐那类播放器一致：

| 模式 | 行为 |
| --- | --- |
| **顺序** | 按列表顺序走，放完最后一首就停 |
| **列表**（默认） | 按列表顺序走，放完最后一首回到第一首 |
| **单曲** | 当前这首反复播放 |
| **随机** | 洗牌袋，一轮之内绝不重复（见下） |

**主界面左下角的循环按钮改的是同一个状态** —— 点它在这四种模式间轮转，
两处 UI 永远同步。两边各记一份状态的话，迟早会出现
「面板显示随机、实际在顺序放」这种事，所以统一收进一个 `setPlayMode()`。

切模式不会打断正在播的歌 —— 模式只影响「下一首怎么挑」，不重排列表本身。

> **单曲循环交给 `<audio>` 原生的 `loop` 属性**，而不是等 `ended` 事件再重播 ——
> 后者在曲末会有一小段空隙，原生循环是无缝的。

#### 随机播放为什么用「洗牌袋」

「每次从全部歌里随机挑一首」听起来很随机，实际体验很差：**两首前刚听过的歌很可能马上又来**。
所以这里改成主流播放器的做法：

1. 把整个歌单**打乱成一袋**（Fisher-Yates）
2. 按顺序往外掏，掏空了才重新洗牌

这样**连着听的 N 首刚好是整张歌单的一个排列**，轮完一遍才会重复。
另外两个细节：

- **两轮交界处不会连着听同一首**：新一轮洗好后如果开头正好是刚播完那首，就重新洗
  （洗完还是撞上就手动调换前两个，不会死循环）
- **手动点播的那首会从袋子里拿走**，否则同一轮里还会再轮到它一次
- 新加入歌单的曲子会**直接丢进当前的袋子**，随机模式下马上就可能轮到

「上一首」在随机模式下沿**实际播放过的路径**回退，而不是随机乱跳 ——
想回到刚才那首，按一下就回得去。

> 文件夹导入有两个上限：最多 3000 个文件、最深 8 层目录，
> 超了会在提示里告诉你。这是防止误选到盘符根目录时把整个盘扫一遍。

### 音乐源

搜索面板顶部可以切换音乐源，**换源后会立刻用新源重搜**，不用再按一次回车。

| 源 | 搜索 | 歌词 | 在线播放 |
| --- | --- | --- | --- |
| **QQ 音乐** | ✅ | ✅ QRC 逐字 | ✅ 用你登录的账号 |
| **网易云** | ✅ | ✅ LRC + 翻译 | ✅ 匿名 320kbps |
| **酷狗** | ✅ | ✅ **KRC 逐字** | ❌ 拿不到地址 |

**酷狗的 ▶ 是灰的**，因为它取不到播放地址（接口要登录 cookie 和签名）。
但它的**逐字歌词质量最好**，拿来给本地曲目配词正合适。同理也加不进歌单 ——
歌单里的在线曲目必须能播。

本地文件的自动配词也走**当前选中的源**：切到网易云，自动匹配就按网易云搜。

#### 为什么没有 Apple Music

不是「接口难找」，是性质不同：Apple Music 的歌词属于 **DRM 保护内容**，
官方只通过 **MusicKit** 提供，必须用你自己的 Apple Developer 账号签发 JWT。
没有匿名接口，绕过就是破解 DRM，所以这里不做。

#### 这些是第三方接口

QQ / 网易云 / 酷狗用的都不是官方开放 API，**没有稳定性承诺，随时可能变**。
所以配了侦察脚本和自检，坏了能立刻定位是哪一环：

```bash
node scripts/test-sources.js          # 三个源逐个体检（搜索 / 歌词 / 解析）
node scripts/probe-sources.js 晴天     # 网易云原始接口
node scripts/probe-sources3.js 晴天    # 酷狗 KRC 链路与解码
```

> 两个容易踩的坑，代码注释里都写了：
> ① 酷狗的 `mobilecdn.kugou.com` 会解析到腾讯云 CDN，证书不匹配，得改用 `songsearch`；
> ② KRC 异或完**直接就是 zlib**，网上不少实现多跳 4 字节反而解不开。
>
> 还有一个不显眼但重要的：**QRC 的字时间是绝对时间，KRC 是相对行首**。
> 界面按绝对播放时间比对，所以 KRC 必须加上行起始，否则整行错位。

### 搜索结果

| 点哪里 | 做什么 |
| --- | --- |
| 整行（封面歌名那块） | **只载入歌词**，不碰正在播的音频 |
| 右侧 ▶ 按钮 | **在线播放**（未登录时提示去登录） |
| 右侧 ＋ 按钮 | **加入歌单** —— 会先确认这首歌真能播，放不了的（没版权 / 需要 VIP）不收 |

「点整行只换歌词」和「▶ 播放」分开是刻意的：想给现有音频换一版歌词时，不该被迫开始播放。

「＋」之所以要先验证，是因为歌单里攒一堆点开就失败的歌毫无意义 ——
验证走的是和播放完全相同的取地址 + 预检流程，不会出现「加得进去却放不出来」。

| 色号 | 出处 | 色值 |
| --- | --- | --- |
| 斑驳紫 | Through Patches of Violet | `#a98bff` |
| 光明橙 | Hero | `#ffa24d` |
| 希望黄 | Fly, My Wings | `#fcfe8b` |
| 清流蓝 | TIAN TIAN | `#57c8ff` |
| 温暖红 | SAIKAI | `#ff6b6b` |
| 黯淡黑 | Gone Angels | `#303030` |
| 沧海蓝 | Compass | `#3224ff` |
| 涟漪粉 | What the Ripple Sees | `#f047ea` |
| 炼狱红 | In Hell We Live, Lament | `#b30000` |
| 清新绿 | 1000x1000 | `#4ede9f` |
| 燃烧红 | Iron Lotus | `#f00000` |

**跟随歌曲自动切色（彩蛋）**：开关打开后，识别到对应曲目就自动换成它的主题色。

内置规则默认**只在艺术家确实是 Mili 时才生效** —— 否则一首第五和弦的《Hero》

想给**非 Mili** 的曲目配彩蛋，在规则里加 `miliOnly: false` 即可（内置和自定义规则都支持）。

## 修改内置色号与彩蛋

### 先搞清楚三种改法的区别

| 你想干什么 | 改哪里 | 要重新打包? | 会进仓库? |
| --- | --- | --- | --- |
| 改名字 / 换颜色 / 删掉 | **软件面板** | 否 | ❌ 只存本机 |
| 加一个只有自己有的 | `data/color-theme.json` | 否 | ❌ 只存本机 |
| **加内置的（所有人都有）** | **改源码**（见下） | 是 | ✅ |

**一句话**：面板和 `data/color-theme.json` 只影响你这台机器；想让别人也有，必须改源码。

### 加一个自己的（不改源码）

编辑数据目录下的 `data/color-theme.json`（第一次运行自动生成，自带说明文字）：

```json
{
  "presets": [
    { "name": "海盐蓝", "color": "#7fd4ff", "song": "某首歌", "builtin": true }
  ],
  "rules": [
    { "label": "海阔天空", "preset": "海盐蓝", "match": "海阔天空|海闊天空" }
  ]
}
```

存盘后**重启播放器**生效。打包版改 `dist\Mili播放器-win32-x64\data\` 下的同名文件。

### 加内置的（改源码）

两个文件，靠**名字**互相咬合：

| 文件 | 管什么 |
| --- | --- |
| `src/main/color-presets.js` | **有哪些颜色** |
| `src/shared/theme-rules.js` | **听到哪首歌切到哪个颜色** |

#### 第 1 步 · 加色号

打开 `src/main/color-presets.js`，在 `COLOR_PRESETS` 数组**末尾**加一行：

```js
{ key: 'ironlotus', name: '铁莲金', song: 'Iron Lotus', color: '#ffd54a', builtin: true },
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `key` | 是 | 唯一标识，小写英文。**加完以后永远不要改** |
| `name` | 是 | 显示名，也是彩蛋规则要找的名字 |
| `color` | 是 | `#rrggbb` |
| `song` | 否 | 出处，只在悬停提示里显示，没有就写 `''` |
| `builtin` | 否 | `true` = 不允许右键删除（仍可双击改名） |

> `key` 为什么不能改：它是「这个色号就是那个色号」的凭据。用户双击改了名字之后，
> 系统靠 `key` 才能认出这还是原来那个内置色号，从而不会每次启动都重新塞一个原名的。
> **改了 `key`，老用户那边会多出一个重复色号。**

#### 第 2 步 · 加彩蛋

打开 `src/shared/theme-rules.js`，在 `RULES` 数组**末尾**加一条：

```js
{
  label: 'Iron Lotus',        // 曲名，触发时提示里显示
  preset: '铁莲金',            // 必须和上面色号的 name 完全一致
  color: '#ffd54a',           // 兜底用，preset 能查到就不需要
  match: /iron\s*lotus|铁血莲华/i,
},
```

**数组顺序就是优先级** —— 从头往后扫，第一条命中的胜出。所以特例要写在宽规则**上面**。

想给非 Mili 的曲子配，加一行 `miliOnly: false`：

```js
{ label: '某首歌', preset: '涟漪粉', color: '#f047ea', match: /某首歌/i, miliOnly: false },
```

#### 正则怎么写

`match` 是拿 **「标题 + 专辑」** 去匹配的（**不含艺术家**），大小写不敏感。

| 写法 | 含义 |
| --- | --- |
| `/compass/i` | 标题里含 compass 就行 |
| `/^compass$/i` | 必须整个标题就是 compass |
| `/fly,?\s*my\s*wings/i` | 逗号可选、空白任意，同时匹配 `Fly My Wings` 和 `Fly, My Wings` |
| `/gone\s*angels\|逝去的天使/i` | `\|` 是「或」 |
| `/(^\|[^a-z])hero([^a-z]\|$)/i` | 独立单词 hero，**不误伤 Heroic** |

两个最容易犯的错：

1. **忘了转义** —— `|` 是「或」，想匹配字面竖线要写 `\|`
2. **写太宽** —— `/hero/i` 会把 `Heroic`、`Heros` 全染上

QQ 音乐上带后缀的很多（`Gone Angels (Library Of Ruina)`、`In Hell We Live, Lament (feat. KIHOW)`），
所以「包含」式写法比 `^...$` 更保险。查真实标题：在软件里搜一下，或用 `npm run test:qq -- "曲名"`。

#### 第 3 步 · 验证并生效

```bash
npm run test:theme     # 校验规则指向的色号真实存在、规则能被自己的标题命中
npm start              # 开发模式看效果（改源码后必须重启）
npm run package        # 重新打包，打包版才会带上
git add . && git commit -m "新增 X 色号与 Y 彩蛋" && git push
```

`test:theme` 会替你抓出名字写错、正则写错这类问题，不用等运行起来才发现。

## 开发与测试

```bash
npm test             # 回归测试（真实拉起两个窗口）
npm run test:theme   # 彩蛋规则 + 规则到颜色的解析
npm run test:presets # 色号合并逻辑（纯 Node）
npm run test:qq      # QQ 音乐链路：搜索 -> 解密 QRC -> 解析时间轴
npm run test:qrc     # 校验 JS 版 3DES 与 Python 参考实现逐字节一致
npm run test:audio   # 本地播放全链路
npm run test:online  # 在线播放全链路（需先登录）
npm run test:login   # 登录窗口能打开
node scripts/test-sources.js   # 多音乐源体检（需要联网，见「音乐源」一节）
```

回归测试覆盖这些容易回退的点：主窗口隐藏后进度仍推进、改设置不重掷落点、
倾角区间真的随机、真换歌时字幕必须重建、找不到歌词时歌词区要有交代而不是一片空白、
换到没有歌词的歌时悬浮窗不能留着上一首的字幕、歌单的去重 / 全选 / 批量移除 /
顺序绕圈 / 随机一轮不重复 / 四种播放模式的 UI 同步与末首分流 / 歌词绑定与删曲解绑。

其中「真换歌必须重建」和「角度互不相同」是刻意加的反向用例 —— 修 A 很容易矫枉过正成 B。
「换歌清空字幕」那条走的是**真实换歌路径**（塞一首假音频进队列后调 `playQueueIndex`），
而不是手工调 `publish()` —— 否则把 `playQueueIndex` 里那句 `await publish()` 删掉用例仍然是绿的。
